# stitch_to_zarr
Stitch tiled microscope images to a compressed OME-Zarr file, using parallel processing as much as possible. Written for multi-channel 3D light-sheet microscope images of mouse brains, it should work for other 3D image types with some adaptations. 

Why would you want to use this? 
- Efficiently stitches large tiled stacks of microscope images to a single, multilevel, OME-Zarr
- Space savings: Initial uncompressed 4-channel, 3x3 tiled image with 900 z-planes: 400 GB raw Tiffs. After stitching, masking & compression: 67 GB.\
- Parallelized workflow: An ancient middle-class laptop (6 years old, 12 cores, 64GB RAM) can run the script on an entire 400 GB image stack in 2h 45 minutes. 
- Multilevel OME-Zarr can be efficiently viewed with e.g. Napari, even on old laptops:

How it works: 
- Stitch the tiled images (per z-plane, using Fiji's "Stitch Grid Collection" plugin) in parallel
- These tiles are then masked to get rid of the information on the outside of the sample (we don't need 16-bit information when it only records sensor noise)
- The mask is created once for the reference channel and re-used for subsequent channels
- Write the resulting plane into an OME-Zarr container
- While processing, also keep track of minimum and maximum intensity values, those are saved in a separate file and can be used for e.g. normalization for deep learning. 
- Downsample for easier 3D viewing in e.g. Napari

Installation: 
1) In a new python environment, make sure you have the following python packages installed:
```
   conda create -n stitch_to_zarr
   conda install -c conda-forge numpy argparse json os re shutil tempfile time math zarr imagej scyjava pathlib itertools skimage dask
```
3) Clone this repository
```
   git clone https://github.com/MoritzNegwer/stitch_to_zarr
```
5) Make sure you have Fiji installed 

Use: 
1) Use Fiji's "Stitch Collection of Grid Images" plugin to generate a TileConfiguration_{zzz}.txt.registered file. Refer to e.g. Figure 5 in the DeepMACT handbook (https://www.discotechnologies.org/DeepMACT/DeepMACT_handbook.pdf) or here for detailed instructions: https://docs.google.com/document/d/1qGpMfJhVyiD46Y55UdF4ELgxd7LcQ8RvSel_lkFrAFQ/edit?usp=sharing

2) Open the stitched image, make sure the overlap is acceptable and there are no tiles missing. Then, determine the threshold by which you can reliably differentiate the empty space around your sample from the sample's background intensity, e.g. using Fiji's "Set Threshold" tool. For our samples, the empty space has a pixel intensity around 100 (thermal noise of the sensor) and background intensity in the 488nm channel is ca. 500. Therefore, setting a threshold of 300 reliably cuts out the empty space and preserves the sample.

3) In the config_stitch.json, adapt the following items:
```
      "fiji_dir":    < directory where your Fiji is installed
      "num_workers": < how many jobs you want to run in parallel. We used 12 workers (number of CPU cores on the test laptop) and did not exceed 40GB RAM usage during processing. If you have less RAM, reduce the number of workers. 
      "start_plane": < where you want to start the stitching. Default set to 1 because plane 0 contains OME-TIFF information and causes Fiji to load the entire stack. 
      "stop_plane":  < last z-plane of your microscope image stack
      "tile_config": < path to the TileConfiguration_{zzz}.txt.registered as generated by Fiji's "Stitch Collection of Grid Images" plugin in step 1)
      "voxel_size":  < add the voxel size of your images (Z/Y/X) in micrometer
      "chunk_shape": < the desired chunking of your zarr array (Z/Y/X). If you don't know what this means, leave at default values. 
```

Per channel, adapt the following:
```      
      "name": "C00_WFA", < The name you want to give the channel
      "channel_number": "C00", < The channel's identifier in the microscope's Tiff output
      "threshold": 300,  < for the reference channel only: The threshold value you determined in step 3) 
      "zarr_output":     < where you want to store the newly created zarr arrays. This folder will be created by the script. 
```
4) activate your python environment and run the script:
```
      conda activate stitch_to_zarr
      python3 ./stitch_to_zarr.py ./config_stitch.json
```
   Alternatively, if you want to save the output to a log file, run the following:
```      
      python3 ./stitch_to_zarr.py ./config_stitch.json > ./stitch_to_zarr_log.txt
```
You can use e.g. Napari to view the output images, using the napari-ome-zarr plugin.

Caveats/Todos:
- Currently only tested on Linux. Need to verify it also works on Windows and HPC cluster environments. 
- This script is built on parallel access to files on a disk, and will presumably be quite slow when reading/writing to the same hard disk. We recommend writing to a separate disk (ideally an SSD) as this will massively speed up processing.
- This script currently omits the first z-plane of the stack, as our microscope's OME-TIFF output contains metadata for the entire stack there, which causes Fiji to try and load the entire dataset into RAM at once when we only want to stitch the first z-plane. Possible solutions: a) Rename the first files to .tiff (omitting the .ome prefix) to deactivate the metadata-dependent stack loading in Fiji, b) reimplement stitching in Python.
- The prototyping of the script was done with the help of ChatGPT, but all performance-critical parts have been rewritten by hand because the LLM kept messing up the chunking/sharding and tried to parallelize at the wrong level. OME-Zarr seems to be niche enough that it's not all that well represented in the training data.
